## Verification (2026-05-23)

**Lesson learned:** Tunebat (Spotify-derived) and `keyfinder-cli` (libkeyfinder) both produced wrong keys on real material. For Message of Love, Tunebat said B min (10A), keyfinder said G♯ min (1A), and **Engine DJ said A min (8A)** — three tools, three answers. Engine DJ is the only one that matters for actually mixing.

**New rule for this tracklist:** trust **Engine DJ first**. The database lives at `~/Music/Engine Library/Database2/m.db`, with the analysed key in the `Track.key` integer. **Don't hand-decode that integer into Camelot — read the Camelot/key Engine actually displays.** The integer is *not* a plain Open Key number, so any formula on it is a guess.

> **Lesson 2026-07-01:** I extrapolated the integer linearly (assumed `key=1`→`1m`, so `key 7`→`7m`→`2A`) and wrote `2A` for the opener tracks — Engine clearly shows them as `11A`. Engine was right; my decode was wrong. This is the same rule as above, applied to my own maths: Engine's display is the truth.

**Confirmed integer → Camelot points** (read from Engine, the only source that counts):

| `Track.key` | Camelot | Musical key |
|---|---|---|
| 1 | 8A | A minor |
| 7 | 11A | F♯ minor |

*Apparent pattern, unconfirmed (verify each in Engine, never trust the formula):* odd values = minor (Camelot "A" side), Camelot number climbs +1 every two steps — `key 1=8A`, `key 3=9A`, `key 5=10A`, `key 7=11A`… Treat as a hint only.

For unverified tracks: add them to Engine DJ, analyze, then re-run this lookup.
